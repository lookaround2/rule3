BUILDER DIFFERENCES FROM PART 2 (read before trusting a status)
   1. Book A Part 3 is a different extraction: pages open with "**PAGE N"; the running head is a line "3-N" or
      "PART 3:COURT ACTIONSR.3.x(y) 3-N" and is also printed inline as "*R.3.x(y)PART 3:COURT ACTIONS". The builder
      removes these heads (the removed text is listed in part_level.BOOK_A.page_furniture_removed). Many spaces are
      missing, footnote numbers are glued to words, footnotes are NOT split out (footnotes = [] with a note), and
      columns are sometimes out of order. Book A rule start = "*Title*3.N" or "*3.N".
   2. compare() has a new tier: texts equal when only letters and digits are compared are NORMALIZATION_ONLY_DIFFERENCE
      with a "basis" note. A status is still only a hint.
   3. parse_official reads Subdivisions; each rule JSON has a "subdivision" field.
   4. Book B: edition year is not printed in the Part 3 files; the builder uses the latest case year cited (2025).
   5. Book A "defined_terms" is a new field (the "Defined Terms" line under Information Note).
   6. All MANUAL_* tables start empty.
   6a. Book A identity (found in the 3.12 pass): Book A is very probably a later edition of Stevenson & Cote, Alberta Civil Procedure Handbook - Book B quotes
      the Handbook 2017 (at 3-21) with the same wording as Book A's 3.12 note, and Book A calls itself 'this Handbook'. No file states the title or edition.
   7. Book B: when the source prints a rule's text twice (heading repeated across a page/file break: seen at 3.4 and 3.12) the parser keeps
      one copy and lists the skipped paragraph ids in sources.BOOK_B.duplicate_rule_text_paragraphs_skipped (added in the 3.4 pass).
   8. Book A: when a rule has no amendment bracket, its text now ends at the first 'Information Note' / 'Defined Terms' / 'Related Provisions'
      heading (before, at the first blank line, which page breaks put inside the rule text). Result: rule text can hold page-end footnote blocks,
      so text notes keep them verbatim. Changed 3.4 and 25 other files; every rule is re-read in its own pass.
