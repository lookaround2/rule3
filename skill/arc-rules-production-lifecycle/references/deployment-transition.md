# Deployment Transition

The packaged skill does not by itself install, disable, or remove predecessor skills.

After the revised skill is validated and installed as the ARC owner:

1. verify the new skill is available and its trigger description is correct;
2. retire/disable the predecessor implicit ARC skills, or replace them with explicit non-implicit redirect/deprecation stubs if backward naming is required;
3. verify only one implicit ARC owner handles source repair, pathway, semantic-production, retrieval-release, rollback, and Appendix requests;
4. preserve predecessor ZIPs/hashes as provenance and rollback evidence;
5. do not claim consolidation is operational until this routing transition is observed.

Current package creation is artifact preparation, not proof that deployment has occurred.
